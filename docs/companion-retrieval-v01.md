# S2 后续：索引版本、检索对照与规则案例验收 v0.1

2026-10-28，接续通用伴学重构 v0.2 与 `companion-continuity-v01.md`。更新源码和本机预览，不替换服务器或公开安装包。

## 本批如何使用

师生原入口保留。新入口为「资料检索与对照」；「学习设计与规则」中新增「案例、反例与验收」。无需模型 Key 即可构建和搜索文字索引、运行对照和查看规则案例。外部 Agent 通过原本本地 MCP 的 `invoke_companion_capability` 使用同一 v4 契约。

1. 选择本机资料范围。教师可选自己的资料库，或自己的资料加某位已配对学生的授权任务；学生读取自己的资料和当前授权任务。
2. 构建索引，输入问题查找候选。命中后打开原资料判断是否正确、适合，而不把相关性分数当置信概率。
3. 先体验原创对照示例，再用自己的问题标注期望来源、可选原句或「不应命中」。保存为固定版本。
4. 选择1—3版索引，以同一题集运行字面匹配和 BM25；保留漏检、误检和异常，旧报告可重新打开。
5. 在规则案例中阅读原文、学习者作品和候选做法，运行工程检查。教师本人逐例审阅，记录理由、专业背景自述、适用范围和本次结论。

内置助手在本机已有索引时获得只读版本清单和检索工具；教师助手只可读取当前所选学生范围与自己的资料库，不会跨学生。索引构建不因模型建议自动发生。云模型使用这些工具时会收到必要命中文本，仍走用户自己的 API；纯检索和对照无需调用模型。

## 索引：可追溯，不改写原件

每版保存代次、父版本、来源 ID / 修订 / SHA256、派生文本哈希、字符分块和重叠、分词器、算法参数、实现版本与清单哈希。相同有效来源和配置复用同版；不同来源或配置生成新代次，不覆盖旧索引。

本批为必要的本地文字索引：

- `literal.v1`：整段查询的字面匹配，作为明确的比较基线。
- `bm25.v1`：词项相关性排序，使用正值 IDF、k1=1.2、b=0.75；英文单词与中文1/2字片段分词。实现依据 [Robertson 与 Zaragoza 的 BM25 综述](https://doi.org/10.1561/1500000019)，本文参数与正值 IDF 选择以存储配置为准，不宣称与第三方实现分数可直接比较。
- 未使用 Embedding 或模型向量，不会因更换聊天模型而重新解释旧向量；向量、语义重排和知识图谱尚未接入。不同分词/算法实现配置不会静默混用。

文字来源包括本机文字资料和授权任务的材料正文；不索引题目答案键、教师私注、未提交草稿或其他学生记录。原图仅索引用户标题和附注，质量状态明确为 `metadata_only_no_ocr`；像素仍须走既有原图通道。不把音频、PDF或图片中的不可见内容伪造为转写。

每次返回结果重查当前授权、最新来源修订、原件哈希、派生文本和分块位置。旧来源修订后排除旧片段，保留版本记录供重建对照；解除配对后不再返回对方材料。历史报告若涉及已撤销任务则拒绝读取，列表不会泄露历史命中文本。引用不是访问凭据。

单次索引上限200份、50万字符；超出及无可读文字的来源明确记为跳过，不宣称整库已覆盖。每次搜索至多10项，按来源去重、返回该来源得分最高片段。每段与原件字符范围一致，仍不保证专业真实性或任务适配。旧任务的适配版本指任务快照，不声称恢复了原教材版次。

## 检索对照：同一标签、真实路径、保留反例

题集记录每题问题、期望来源、可选精确原句、标注理由与标签来源。标注只代表用户/合成设计预期，不由保存动作自动专业审定。题集可修订为新版本，旧版本、case_set_hash 和报告继续保留。简易网页每题编辑一个期望来源；MCP 支持多个。已有多来源标签不由简易网页静默删减。

每次对照冻结题集版本/哈希、索引清单和算法配置、k、当前可用语料哈希及逐题命中片段。使用真实 `index.search` 排序路径，不用模型自报效果。结果指标：

| 项目 | 含义与分母 |
|---|---|
| Hit@k | 有答案且当前可评问题中，至少找回一个标注来源/原句的问题占比 |
| MRR@k | 这些问题首个正确结果倒数排名的平均值；未命中为0 |
| 无答案误检率 | 当前可评无答案问题中，出现任何候选结果的比例 |
| 未计分 | 标签来源版本变化或缺失，不记为普通漏检或成功 |
| 执行失败 | 配置不匹配或排序失败，单列并排除质量分母；不是无答案 |
| 时间 | 本机每条查询的单次耗时，仅作排查线索，不作为稳定性能结论 |

没有相应题目时指标为 null，而不是伪造100%。来源或处理范围不同的对照显式标记 `corpus_or_processing_changed`，不能将差异全部归因于算法。查询候选因未标全而与标签不同也可能仍有价值；应回看逐题结果再修订标注，而不自动改题集以美化指标。

不同调用的搜索耗时会不同，但命中及来源语义共用门面。保存的对照使用请求回执重放，HTTP、独立 stdio MCP 和 HTTP MCP 可返回同一报告。旧结果不会因重新运行而被覆盖；运行后来源变化另标当前状态。

## Policy Pack：案例、反例、工程检查、实际审阅

`aesthetic/cases/learning-policy-cases.v1.json` 提供20个原创合成案例，P01—P10各一正例、一反例。每例有原始材料、学习者作品/条件、候选做法、来源、情境边界、专业审阅要点、输入和自动检查预期。覆盖修辞目的、听力、写作、口语、数学和编程；具体操作和形式不跨情境硬套。

听力/口语案例未配真实录音，明确列为证据缺口；音频存在的测试输入只是工程模拟，不证明真人音源或声音质量。教师不得据此签成已完成真人试听或口语评分。

工程检查冻结当前十包、引擎版本及案例内容哈希，验证条件、阻止行为或保留待审等程序约定。P03专业前提、P07语用质量、P09真实负担等任意语义内容，当前不能仅凭这些断言自动识别；反例的程序行为符合预期不等于反例做法获准。这些内容必须继续专业审阅，不制造一个误导性的「全审美通过率」。

教师审阅是追加记录：

- 精确绑定检查记录、规则包及案例哈希，逐例评价规则处理是否合适、需要修订或不确定，并说明依据。
- 声明审阅人、相关专业背景、适用范围，结论可为需修订、不采用、仅限定范围试用。
- 限定试用需工程条件通过、该包正反例全部完成且处理被评价为合适。版本变化后原结论标为需重审。
- 本机教师角色和 `human_confirmed` 是当前调用者声明；它们不证明人类身份、专家资质或真实教学效果。Agent 不得替实际教师填写确认。
- 审阅不修改生产规则、不自动发布跨人方法、不向学生同步所有内部审阅记录。真正的范围试用、效果证据与公共方法发布仍是后续独立步骤。

本轮通过的是案例载入、条件执行、引用/版本和审阅记录流程；领域审定与真实学生效果仍为 `NOT_REVIEWED` / `NOT_TESTED`。

## 三层与契约保持不变

| 层 | 本轮增加 |
|---|---|
| 审美层 | 原创案例及专业审阅判据；工程断言与专业结论分开 |
| 功能层 | v4契约、当前授权来源装配、真实检索/对照 Harness、限定审阅记录和助手只读工具 |
| 资产层 | 分块、分词、来源身份和配置版本；原始资料、索引、标签、报告与方法案例分开管理 |

新增 `companion.capability.v4`；v1—v3 Schema保留。操作、载荷 Schema 均可由 `architecture.describe` 读取。既有网页、MCP、BASE与配对不迁移，新能力继续走 `LocalRuntime.invoke_capability`。固定三层依赖检查不放宽，也不新增任意代码执行能力。

v3之后新增五表：`companion_indexes`、`companion_benchmarks`、`companion_retrieval_runs`、`companion_policy_checks`、`companion_policy_reviews`。保留原表和记录；沿用同一加密数据库备份。v4首次调用创建扩展表，旧v1读不初始化新表。版本比较和请求回执避免覆盖及重复运行；并发构建代次冲突需重新构建。

无新增运行依赖。Python包需携带案例 JSON 和新增静态文件；本轮构建/检查包内容，不代表公开 Windows 安装包或服务器已升级。

## 复现

```powershell
$env:PYTHONPATH='src'
python -m pytest tests -q
python scripts/check.py --business
python scripts/verify_companion_retrieval.py
node --test tests/workspace-state.test.cjs
```

独立集成脚本仅创建合成资料、两个索引配置、固定题集和「需要修订」的流程声明，不批准真实教师试用。它验证真实HTTP、独立stdio MCP和HTTP MCP，不重新声称公网 WebRTC 验收。`artifacts/companion-retrieval-verification.json` 保存实际对照结果，包括候选方法带来的负例误检。

下一步应由相关教师填写真实场景题集、审阅专业反例和缺失媒体，再决定是否接入语义检索或修订规则。不要用合成题集的小样提升替代教学效果，也不先根据单一算法的命中率选定全局最佳实现。
