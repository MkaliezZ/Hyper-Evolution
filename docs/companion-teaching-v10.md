# 教学链补全 · v10 能力契约

2026-11-02，源码工程版。保留既有 v1—v9、本地网页、MCP、签名师生配对和独立学科目录。本轮围绕 11 月 2 日逐项对照中的 15 项部分覆盖补缺，合并成现有教学链上的 8 组工作。官网 0.5.0 安装包未在本轮替换。

## 三层分工

| 层 | 本轮职责 | 位置 |
| --- | --- | --- |
| 审美层 | 来源与范围匹配、词形核对、整卷覆盖、基础题适用边界、先核对再训练再复测的教学顺序 | `aesthetic/teaching_workflow.py`，复用既有 `aesthetic/academic.py` |
| 功能层 | 教师身份与当前学科授权、事务恢复、局部改稿、组题、目标映射、班级逐人执行、报告装配 | `functional/teaching_workflow.py`、`teaching_reports.py`、`teaching_contracts.py`；模型使用既有 `academic_agent.py` |
| 资产层 | 草稿及规则依赖指纹、题目复用来源、文本抽取定位、版本引用、签名作业蓝图公开投影 | `assets/teaching_workflow.py`，复用 append-only `academic_store` |

三层继续由同一个 `LocalRuntime.invoke_capability` 接通网页、内置助手和外部 Agent。新增 v10，没有修改旧版本请求、结果和负载 Schema。新记录使用 `workflow_*` 名称，保存在当前英语工作区的既有数据库中；加密恢复包自动包含这些记录。

| 20 目标复测 | 固定目标编号与版本，布置前映射题号，跨新题任务追踪历史，修改目标后区分旧版本结果 | 原目标确认与独立条件评价 | 待评、未知帮助、无效题沿用既有判断，不填成零分 |
| 21 学习报告 | 目标覆盖、本周提交、待评、学习版与家长版报告下载 | 原逐题记录与学习报告 | 家长版省略教师私注；由教师选择保存和发送 |
| 22 下一步安排 | 依据当前报告生成“核对 → 训练 → 未见题验证”的有日期候选安排 | v5 学习安排、修改预览、确认与签名发布 | 每周次数少时，本轮三步可以跨周；老师核对后明确发布 |
| 24 班级布置 | 冻结名单、逐人路线和等价范围映射、逐人校验、部分失败保留、原请求重试未成功成员 | 原班级名单、已审源草稿与签名作业 | 内容不等价时提示单独备题；不会把源学生范围冒充其他学生范围 |
| 25 分组证据 | 共同冻结题目/目标/语义等价范围下，联合返回原题、原答、日期、已记录原因及评分 | 原原因记录、独立目标结果 | 提供候选证据，由教师决定是否分组 |

## 教师从哪里使用

1. 教学首页的“预登记学生”：先登记，配对后关联设备。
2. 学科与路线 → 英语 → K12英语教学 → 练习与审题：输入考点与题数，查题库并准备候选，或选择自己的 API 补缺。
3. 同页“继续一份草稿”：续审、单题修改、继续补题、整卷蓝图、选入教师题库、关联固定复测目标。
4. “教材与范围”：目录登记/文本抽取/导入，预览并确认后应用；扩展词表检查；安排后续单元备课。
5. “问题与学习报告”：登记固定目标、查看历次复测、下载学习版/家长版报告、生成下一轮候选安排。
6. “班级与批量布置”：逐人映射后布置，查看批次并重试失败者，比较共同条件下的原始作答证据。
7. 教师打开已布置任务：明确撤回并可关联已发布的替换任务。

学生继续使用现有“我的任务、反馈、老师的规划、学习安排”。新增内容只有已布置任务的公开蓝图和可选本机练习计时。已交目标测验保持原答，不重新开启计时或覆盖施测记录。

## MCP / Agent 接入

调用 `get_companion_architecture`，从 `data.teaching_extension.payload_schemas` 获取实际契约；工具 `invoke_companion_capability` 支持：

```json
{
  "contract_version": "companion.capability.v10",
  "request_id": "teacher-preparation-unique-id",
  "operation": "workflow.prepare",
  "peer_id": "从实际配对列表取得的学生ID",
  "payload": {"route_id": "实际路线ID", "focus": "细节理解", "count": 5, "scope_ids": []}
}
```

读取后再执行，使用当前学生与学科。`workflow.prepare` 只准备候选；外部 Agent 可用自己的模型生成缺题，再通过既有 `k12.draft.save` 或新 `workflow.merge` 存入。网页内置助手使用 `/api/local/jobs` 的 `k12_workflow` 模式，调用本机配置的用户 API。两种方式均须明确确认人工审校和布置。

关键操作族：`roster.*`、`curriculum.*`、`lexical.check`、`blueprint.*`、`workflow.prepare/resume/merge`、`draft.patch/review_items/finalize_review`、`bank.*`、`prep.*`、`goal.*`、`report.*`、`publication.withdraw`、`class.assign/report/evidence`。

相同请求号只用于相同内容的恢复或重试。修改内容或版本后使用新请求号。`class.assign` 会冻结原映射；相同请求号重试仅补执行未成功成员，成功成员的任务 ID 保持不变。

## 验证与保留项目

运行 `python -m pytest tests -q`、Node 单测、`python scripts/check.py --business` 和 `python scripts/verify_teaching_workflow.py --browser`。后一个验证实际 HTTP、stdio MCP、HTTP MCP、签名同步和两种角色的浏览器页面；只生成合成测试数据，不调用付费模型。模型结构流程使用可控 FunctionModel 验证，实际教学质量与真人试用另行验收。
