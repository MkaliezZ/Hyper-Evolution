# 托福邮件写作双端演示

`toefl-2026-email-demo.json` 是团队原创合成案例，包含任务材料、目标、三项完成标准、带缺口的首稿、具体反馈、修订稿和新情境复测。参照 ETS 的 Write an Email 沟通任务，不是官方真题或官方评分量规。

复用时先在英语工作区选择留学路线，并核对演示学生档案的考试类型。将 JSON 中的 `material` 作为文字资料保存；这里没有声明网页可直接导入此 JSON。

1. 教师通过“投石问路”梳理目标并单独分享。
2. 从文字资料选择“用这段资料学习”，选择“写作组织与修订 / 应用与表达”，填入 `goal` 和 `criteria`，预览后布置。
3. 在配对学生端提交 `first_draft`，如实填写合成演示和帮助声明。
4. 教师端核对预审候选的原文引用，采用后修改并保存本机草稿。外部 Agent 可通过 `review.context` / `review.capture` 提供候选，网页也支持教师配置自己的 API 后生成。
5. 实际教师亲自核对后再确认发送。工程演示使用明确标注的无分数 Agent 反馈；不代签真人确认，不发布达标或掌握判断。
6. 学生提交 `revision`；另布置 `retest.material`，保留新情境作品及全部历史。

本次实机演示使用同一电脑的两个独立合成档案，通过真实本机 WebRTC 同步。验证了两道任务、三次作品提交、原答与修订留存、外部 Agent 预审和可编辑草稿；未验证真人教学效果、官方评分或跨公网中转。

初次任务沿用旧演示档案的 `ielts` 元数据，运行的是明确绑定的 writing 场景和自定义邮件标准；这份不可变快照保留。复测前已将教师侧演示学生档案切换为 `toefl`。复现时请在创建任务前核对档案，避免继承旧标签。视频以邮件沟通专项学习流程呈现，不作为考试引擎验收。

视频、实际页面截图、字幕、章节和执行证据保存在工作区 `outputs/toefl-demo-video-v0.1/`，未打包个人数据或 API Key。
